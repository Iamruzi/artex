# 二开版质量整合设计

目标是以二开 `361ae73` 为主体，吸收官方 `e6ec569` 中遗漏的基础修复与可观察性功能。用户明确要求保留二开已有能力，不采用整文件覆盖或上游整体替换。

## 方案

采用按功能提取：鉴权、连接池、页面布局、播报板分别落地；noa 保持默认关闭，Worker 回看保留可配置工具绑定。整体 merge 的冲突面覆盖二开的安全、会话、隧道和验证装配；以上游重建又需要重做这些扩展，因此两者都不适合此次整合。

## 必须保留

- session/tunnel/recon/stage、凭据、拓扑、移交、待授权网段与任务级代理。
- chains、反证验证、finding 合并、停滞检测、超时与冻结感知。
- guard、目标内容不可信规则、蜜罐识别、出口审查与现有工具注册。
- refresh cookie、access token 版本吊销、SSE ticket、门控与用户已编辑的工具绑定。
- 当前依赖版本，不回退 norma。

## 数据与错误处理

首次设置密码使用数据库主键保证仅插入一次；读取失败返回 503。连接池采用上游明确的容量和寿命设置。播报按当前任务分页，不混入继承来源节点。noa 与内置会话压缩互斥，接入失败保留原机制，按 run 读取开关。

Worker 回看工具由现有工具管理页控制，新设置不强制重绑老库；可选启用时同时恢复搜索、详情与节点工具的默认注册能力，保留已有 guard 与来源边界。

## 验证

对首次写入、错误处理、密码边界增加回归测试；复用现有鉴权、代理、会话、隧道、chains 与验证测试。检查 Go 构建/vet、前端类型与静态构建。数据库测试必须区分实际运行与环境跳过；没有靶场运行时不声称提升通关率。
